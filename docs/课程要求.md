# 专创融合课程项目要求

一、作业方向：

面向大模型智能体的 Skill 自进化

二、任务描述：

大模型智能体（LLM Agent）能够通过自然语言理解、任务规划、工具调用以及环境交互完成复杂任务，但传统智能体通常依赖固定提示词、固定策略或人工设计的工具使用流程，在面对连续任务时难以有效利用过去的成功与失败经验。如何让智能体从交互过程中自动总结可复用的经验，并形成、更新和调用 Skill（技能），是实现智能体持续学习和自进化的重要方向。

本项目围绕“智能体 Skill 自进化”开展课程实践。要求同学们设计一个能够在任务执行过程中积累经验、形成 Skill，并在后续任务中检索和使用 Skill 的智能体系统。项目重点不是训练一个新的大模型，而是研究如何利用大模型的上下文学习、反思、经验总结和 Skill Library 等机制，在不更新或少量更新模型参数的情况下，使智能体随着任务经验积累而提升。该方向与现有基于语言反馈的经验学习、技能库以及经验抽取方法具有较强的关联性。

1. 基础任务：

选择一个具有明确任务反馈的智能体环境，使智能体完成一组任务，并实现如下基本流程：

任务执行：智能体根据自然语言任务与当前环境状态进行规划和行动。

经验记录：保存任务目标、执行轨迹、成功/失败结果以及必要的环境反馈。

Skill 提取：从成功轨迹或失败案例中总结可复用的技能，包括技能名称、适用条件、执行原则以及注意事项等。

Skill 检索：面对新任务时，根据任务描述从 Skill Library 中检索相关技能，并将其注入智能体上下文。

Skill 更新：根据后续任务执行结果，对已有 Skill 进行新增、修改、合并或淘汰，使 Skill Library 随经验积累逐步演化。

- 其中，Skill 可以采用自然语言文本或简单 JSON 结构进行保存。例如，一个 Skill 至少应包含：skill_id、skill_name、description 等字段。鼓励同学们根据具体任务设计更加合理的 Skill 表示。

2. Skill 自进化机制设计：

在完成基础流程的基础上，每组至少设计一个针对 Skill 自进化过程的改进方法。可以围绕“什么经验应该成为 Skill、Skill 什么时候应该更新、多个 Skill 如何组织、错误 Skill 如何被发现和淘汰”等问题开展。示例包括：

基于任务结果的 Skill 更新门控：只有满足一定质量条件的经验才能进入 Skill Library。

Skill 质量评分：从成功率、复用次数、任务相关性等维度评价 Skill，并对低质量 Skill 进行降权或淘汰。

Skill 版本管理：保存 Skill 的历史版本，并根据后续执行结果回滚或更新。

Skill 冲突处理：检测内容相互冲突或重复的 Skill，并进行合并、保留或淘汰。

层次化 Skill：将通用 Skill 与任务/场景特定 Skill 分开管理。

Skill 泛化：研究从训练任务中获得的 Skill 能否迁移到未见过但具有相似结构的新任务。

以上仅为示例，不要求全部实现。鼓励同学们围绕一个具体问题进行深入设计，而不是简单堆叠多个模块。

3. 基础实验：

至少完成以下三项实验，并保存完整日志：

① 无 Skill 基线：不提供历史 Skill，仅依靠基础 Agent 完成测试任务。

② 静态 Skill：预先提供一组 Skill，但测试过程中不允许更新 Skill Library。

③ 动态 Skill：允许智能体根据任务执行结果自动产生和更新 Skill，并在后续任务中使用。

统计任务成功率，并保存典型成功/失败案例。

4. 进一步的对比实验（至少 1 个因素）：

围绕 Skill 的获取、检索或更新机制选择 1 个或多个可控变量进行定量实验。例如：

Skill 更新阈值：比较“每次失败都更新”“达到一定成功/失败次数后更新”等策略。

Skill 检索数量 Top-k：比较不同 Top-k 对任务成功率和上下文长度的影响。

Skill 表示方式：比较完整经验、简短原则、结构化 Skill 等不同表示。

Skill 更新方式：比较新增 Skill、覆盖更新、版本化更新、合并相似 Skill 等方法。

反馈来源：比较环境显式反馈、任务结果、LLM 自我反思等不同反馈方式。

Skill 使用策略：比较始终注入、按任务相关性检索、按历史成功率筛选等方法。

要求给出曲线或表格，并对实验结果进行原因分析；无论改进后性能提升、不变或下降，都需要结合实验现象进行解释。

5. 评价标准：

项目的核心评价对象是“Skill 是否真正帮助智能体从经验中学习”，而不是模型参数规模或单次任务的最高性能。

6. 建议任务环境：

建议选择容易运行、结果容易判断的文本类任务，不要求复杂的视觉、机器人或强化学习环境。只需要选择一个任务环境即可。

推荐：ALFWorld、WebShop、Search-QA 等已有文本环境。

也可以自行设计一个简单任务环境，例如文本问答、简单信息检索、规则推理、旅行规划、购物选择等，但需要具有明确的任务目标和可判断的成功标准。

7. 算力与模型要求：

推荐使用大模型 API 或本地开源模型完成实验。

不要求模型训练，如 SFT 和 RL 后训练。

建议先使用少量任务调通完整流程，再扩大实验规模，避免产生过高 API 费用。

8. 环境与工具推荐：

Python：推荐 Python 3.10/3.11。

LLM：GPT 系列、Claude 系列、Gemini 系列等闭源模型，或 Qwen系列、Llama 系列等开源模型。

Agent 框架：可使用 LangChain、LlamaIndex 等成熟框架，也可以自行实现轻量 Agent Loop。

向量检索：可使用 sentence-transformers、FAISS 等轻量工具，也可以采用关键词匹配作为 baseline。

数据与日志：推荐使用 JSON/JSONL 保存任务轨迹和 Skill Library，便于后续分析。

本项目优先考虑可复现性和实验设计，不要求使用复杂框架。只要能够清楚展示 Skill 的产生、存储、检索、使用和更新过程即可。

三、组队：

由修课同学组队（每组人员≤3人）。建议组内进行模块化分工，例如：Agent 执行与环境部分，Skill 提取与更新部分，实验分析与系统集成部分等。可根据实际情况灵活调整。

四、输出物：

中期：中期方案（技术创新报告）+系统演示（可选项）

期末：一篇总体方案（综述报告+技术创新报告）+系统演示

五、附加分：

专利申请或学术论文

六、重要时间节点：

中期：每组汇报大模型智能体自进化技术方案；

第十七周：检查总体实现和各个报告文档；

七、报告与实现要求：

1、综述报告包括：题目、摘要、国内外研究现状+国内外相关工作陈述、结论和参考文献；

2、技术创新报告包括但不限于：引言、对任务的设计和分析、智能体及 Skill 自进化实现方案（方法）、实验结果、结论和参考文献。

3、系统代码实现要求：

情况一、如无参考开源项目，则在报告中详细阐述技术路线和实现方案；情况二、如参考开源项目，则在报告中注明项目来源，写清项目网址，在报告中写清楚项目创新点，并最终需要在代码中注明每一个创新点。

#### 注意：如使用开源代码不经创新修改，并且不在报告和代码中注明的小组，一经查实从严处理！！
